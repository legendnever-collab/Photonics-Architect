# Campaign Registry and persistence

`src/campaign-registry.js` is the authoritative Level1–11 contract. Each record defines ID, number, title, goal, focus, kind, solver scope, required test conditions, completion predicate, next ID, entry action and available solution keys. Goal Card, Level Selector, Next, completion display and Solution lists/numbers read this registry. Existing physics BRIEFS retain numerical requirements; they are solver parameters, not a second navigation registry.

Next is explicit. A Fresh Test under the current Level completion predicate is required. Preview, STALE, Resume and historical completedLevels cannot advance. Snapshot is a distinct action. Final Level has Campaign Complete / Free Design / Compare / Continue Editing; it does not create a twelfth Level or change the current architecture. Free Design is an optional UI continuation mode for editing the existing design; existing solver validity/score conditions remain visible.

Transitions preserve current components, params, IDs, positions and actual nets.5→6 keeps the100G NRZ engine and marks it unsupported for the new400G PAM4 task; it does not magically upgrade modulator/EIC hardware or erase the layout. Player may edit/delete/replace appropriate parts, use a validated solution, or explicitly start a separate Architecture.6→7 also retains the400G engine.8→9 retains the1.6T engine and creates an explicit Package state;9→10 adds thermal conditions;10→11 adds stress/assembly predicates.

Campaign Design preservation is separate from Physics Design state: IndexedDB key `campaign-ui-v051`, version1, contains up to11 `{level,name,solverVersion,design}` records, one latest preserved Design per Level. Designs are captured before transitions / explicit new or practice designs. The archive is independent of the six-Snapshot limit and the existing protected Solution backup. Returning to an older preserved Design keeps the union of campaign completion history but requires Fresh Test. Earlier iterations can additionally be retained as existing named saves or snapshots.

JSON Export includes outer `campaignArchive`, alongside Physics `design` and independent `referenceBackup`. Import validates all archive entries (unique known Level IDs / matching design brief / bounded11 / normal design validation) before installation. Exports/imports from earlier versions without this outer field remain valid. Raw original save/archive and protected Solution backup keys are not deleted. No new Physics schema is required: schema3/4/5 continue; new metadata is optional and external to the Physics payload.

Read-only result view settings use separate IndexedDB key `engineering-ui-v051`: tab, source mode, selected Lane and baseline index. They do not affect solver freshness or the package Monte Carlo fingerprint. Existing mobile studio view settings and original recovery paths remain.

UI entry action from Level Selector keeps the Library Panel open for subsequent construction controls. Explicit Next closes mobile panels to show the new Goal and Canvas. No automatic Next occurs on success. Completion Card is non-modal, compact and collapsible; actual same-condition Baseline deltas are shown when one exists. No fabricated improvement percentage, badge/currency/timer or repeated celebration animation is introduced.

Assembly freshness now compares canonical Physics route inputs: source/destination/mode/waypoints and geometry kind/units/scale. Export-derived points/length/loss/validation display fields are ignored. Existing v0.5 fingerprint records are canonicalized for comparison without changing original data. JSON Paste therefore does not invalidate a physically identical completed Assembly run; actual route/seed/profile/physics changes still invalidate it.
